# FLX lock screen audit and implementation

The compositor in `src/comp/shell.c` owns lock-screen rendering and input using FLX's own rasterizer and widgets; there is no GTK or other UI toolkit. PID 1 starts `/bin/flx-authd`, a native Rust service that accepts requests only over `/run/flx-auth.sock` (mode 0600). On first use, the lock screen asks the user to create and confirm a password of at least 10 bytes. `flx-authd` creates a random 16-byte salt and stores only a PBKDF2-HMAC-SHA256 verifier (180,000 rounds) in `/home/.config/flx-auth.db` with mode 0600. BearSSL supplies the audited HMAC/SHA-256 primitives. Five failed attempts trigger a 20-second service-side delay. Passwords are neither written to logs nor persisted in plaintext. There is no in-UI password reset yet; resetting a forgotten password requires administrative recovery access.

The slider opens the native credential dialog; it cannot unlock the session. Only a successful first-time enrollment or password verification starts the unlock transition. Enter submits, Backspace edits, and Escape cancels. If `flx-authd` is unavailable, the screen remains locked and reports that state.

The current FLX process model still runs PID 1, the compositor and application processes as root. The socket and verifier are protected by root-only file permissions, but same-UID root applications can access them; full protection against a compromised application requires per-user UID separation and a privileged broker. The current account system also lacks password-backed account switching and a suspend backend, so these are not represented as working actions.

The lock screen uses the selected FLX wallpaper without blur, a proportionally positioned French clock/date and quote, a compact Wi-Fi indicator and a horizontal drag slider with a deliberate completion threshold. A simple click or Enter does not unlock it. A small power popover exposes shutdown and restart through PID 1; suspend and user switching are not implemented. Battery percentage appears only when `/sys/class/power_supply/BAT0/capacity` can be read and parsed; other battery naming conventions are not detected.
