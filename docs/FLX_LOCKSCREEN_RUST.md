# FLX lock screen audit and implementation

The compositor in `src/comp/shell.c` owns lock-screen rendering and input using FLX's own rasterizer and widgets; there is no GTK or other UI toolkit. PID 1 starts `/bin/flx-authd`, a native Rust service that accepts requests only over `/run/flx-auth.sock` (mode 0600). The service stores its PBKDF2-HMAC-SHA256 verifier (180,000 rounds, random 16-byte salt) in `/home/.flx-system/auth.db` (mode 0600), inside a root-owned mode-0700 directory on the persistent home disk. BearSSL supplies the HMAC/SHA-256 primitives. Five failed attempts trigger a 20-second service-side delay. Passwords are neither written to logs nor persisted in plaintext. On first boot, an empty credential store opens directly to the desktop; the first explicit lock-screen enrollment still asks the user to create and confirm a password of at least 10 bytes.

For a normal lock, the slider opens the native credential dialog and cannot unlock the session by itself. After resuming from a successful system suspend, an already authenticated session returns with the slider alone. Enter submits a credential, Backspace edits, and Escape cancels. If `flx-authd` is unavailable, the screen remains locked and reports that state. Settings can change the password after checking the current password, generate a random one-time recovery code, and consume that code to reset a forgotten password. Recovery codes are stored only as salted PBKDF2 verifiers and must be saved by the user when displayed.

PID 1 and the compositor remain trusted root processes. The compositor launches only registered applications, closes inherited DRM/input/console descriptors, clears supplementary groups, sets `no_new_privs`, and drops each app to UID/GID 1000. It records Unix peer credentials and blocks privileged power requests from app UIDs. Applications cannot open the root-only authentication socket or read the verifier; the compositor brokers only password change and recovery commands that require the current password or recovery code. The current release still has one desktop UID and one credential record. Therefore this boundary protects root services from an app compromise, but does not isolate apps from one another or provide independent user homes. Multiple Linux users, role management, and password-protected account switching remain unimplemented.

The lock screen uses the selected FLX wallpaper without blur, a proportionally positioned French clock/date and quote, a compact Wi-Fi indicator and a horizontal drag slider with a deliberate completion threshold. A simple click does not unlock it. The power menus expose shutdown, restart, and suspend; suspend writes `mem` to `/sys/power/state` and depends on kernel and firmware support. The kernel fragments enable suspend for x86_64 and arm64. QEMU suspend/resume could not be exercised in this build environment. User switching is not implemented. Battery percentage appears only when `/sys/class/power_supply/BAT0/capacity` can be read and parsed; other battery naming conventions are not detected.
